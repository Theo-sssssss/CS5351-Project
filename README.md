# CS5351 Software Engineering Project / CS5351 软件工程课程项目

This repository contains a six-person team project for CS5351 Software Engineering.

本仓库用于管理 CS5351 软件工程课程的六人团队项目。

## Project Status / 项目状态

The team will select a bounded, original software engineering tool that assists software developers or development teams. The tool must solve a measurable development-workflow problem; it is not an end-user application.

团队将选择一个范围明确、具有原创性的开发者工具，帮助软件开发者或开发团队完成特定工作。该工具必须解决可衡量的开发流程问题，而不是面向普通用户的应用程序。

## Core Constraints / 核心约束

- Team size / 团队人数: 6 members / 6 人。
- Effort / 工作量: each member contributes approximately 30-40 productive hours / 每位成员约投入 30-40 小时有效工作时间。
- Process / 过程: at least three Agile sprints, with a standing weekly meeting and a burndown chart / 至少进行三个敏捷 Sprint，每周固定例会并维护燃尽图。
- Non-functional requirements / 非功能需求: define at least two, each supported by an architectural design choice and rationale / 至少定义两项，每项均须有架构设计选择及其理由。
- Evidence / 过程证据: preserve weekly issues, plans, decisions, code, tests, reviews, risks, and unresolved technical debt in this repository / 每周在仓库中保留 Issue、计划、决策、代码、测试、评审、风险和未解决技术债。
- Delivery / 交付: source code on GitHub, a final report in IEEE Transactions on Software Engineering format, and a presentation/demo video / GitHub 源代码、IEEE TSE 格式的最终报告，以及展示和演示视频。

## Working Structure / 仓库结构

- `docs/project-requirements.md`: course requirements and team execution baseline / 课程要求与团队执行基线。
- `docs/`: architecture, sprint records, evaluation plan, and report materials / 架构、Sprint 记录、评估计划和报告材料。
- `src/`: implementation after the project scope is selected / 选题确定后的实现代码。
- `tests/`: automated and acceptance tests after the project scope is selected / 选题确定后的自动化测试和验收测试。

## Next Decisions / 下一步决策

1. Choose the team name and project name. / 确定团队名称和项目名称。
2. Define the target developer workflow, user, trigger, current failure, measurable outcome, and non-goals. / 定义目标开发流程、用户、触发条件、现有失败点、可衡量结果和非目标。
3. Select at least two non-functional requirements and record their architectural rationale. / 选择至少两项非功能需求，并记录架构理由。
4. Create Sprint 1 issues, acceptance criteria, and an evaluation baseline. / 创建 Sprint 1 的 Issue、验收标准和评估基线。
